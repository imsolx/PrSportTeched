# การเข้าทดสอบใช้งานระบบหลังบ้าน

เอกสารนี้ใช้สำหรับผู้ดูแลระบบและผู้ทดสอบที่ต้องการเข้าตรวจสอบหน้าหลังบ้านของระบบ TECHED SPORT / RMUTT Sports MVP บนเครื่องทดสอบหรือเครื่องพัฒนา

## ข้อมูลสำหรับเข้าใช้งาน

- URL หน้าเว็บ: `http://localhost/prsport/`
- ปุ่มเข้าสู่ระบบ: `เข้าสู่ระบบ` ที่มุมขวาบนของหน้าเว็บ
- อีเมลเริ่มต้น: `admin@rmutt.local`
- รหัสผ่านเริ่มต้น: `Temp@1234`
- สิทธิ์เริ่มต้น: `super_admin`

หากมีการกำหนดค่าในไฟล์ `.env` ให้ใช้ค่าจากตัวแปรต่อไปนี้แทนข้อมูลเริ่มต้น

```bash
PRSPORT_ADMIN_EMAIL=admin@example.com
PRSPORT_ADMIN_PASSWORD=your-password
```

หมายเหตุ: ระบบจะสร้างบัญชีผู้ดูแลเริ่มต้นเฉพาะตอนที่ตาราง `users` ยังไม่มีผู้ใช้เท่านั้น หากฐานข้อมูลมีผู้ใช้อยู่แล้ว การแก้ `.env` จะไม่เปลี่ยนบัญชีที่มีอยู่โดยอัตโนมัติ

## การเตรียมระบบก่อนทดสอบ

1. เปิด Apache ผ่าน XAMPP
2. ตรวจสอบว่าโปรเจกต์อยู่ที่ `C:\xampp\htdocs\prsport`
3. เปิดหน้า `http://localhost/prsport/`
4. ตรวจสอบว่าโหลดหน้าแรกได้ และเห็นเมนูสาธารณะ เช่น กีฬา นักกีฬา ตารางแข่งขัน ผลการแข่งขัน และข่าวสาร
5. กด `เข้าสู่ระบบ` แล้วกรอกบัญชีผู้ดูแล

หลังเข้าสู่ระบบสำเร็จ เมนูหลังบ้านจะแสดงเพิ่ม เช่น แดชบอร์ด กีฬา นักศึกษา ทีม การแข่งขัน ข่าวสาร แผนงาน ผู้ดูแลระบบ และรายงาน

## รายการทดสอบหลักของระบบหลังบ้าน

### 1. แดชบอร์ด

- เข้าหน้า `แดชบอร์ด`
- ตรวจสอบตัวเลขสรุป กีฬา ทีมที่อนุมัติ นักศึกษา แมตช์จบแล้ว และงานค้าง
- กดปุ่ม `สรุปงาน` เพื่อตรวจสอบการสรุปด้วย AI หรือ fallback ภายในระบบ
- ตรวจสอบตารางกิจกรรมล่าสุดว่ามีรายการหลังจากบันทึกข้อมูล

### 2. กีฬา

- เพิ่มกีฬาทดสอบ โดยระบุชื่อ ประเภท เพศ จำนวนผู้เล่น และไอคอน
- แก้ไขข้อมูลกีฬาจากตารางรายการกีฬา
- ทดสอบลบรายการที่สร้างขึ้น
- ตรวจสอบว่ากีฬาที่เปิดใช้งานแสดงในหน้าสาธารณะ `กีฬา`

### 3. นักศึกษา

- เพิ่มนักศึกษาทดสอบ โดยระบุรหัสนักศึกษา ชื่อ นามสกุล สาขา ปีเข้า เพศ และเบอร์โทร
- ทดสอบค้นหาและแก้ไขข้อมูลจากตารางนักศึกษา
- ทดสอบนำเข้า CSV ด้วยรูปแบบหัวตาราง:

```csv
student_code,prefix,first_name,last_name,department_code,entry_year,gender,phone
```

- ตรวจสอบกรณีข้อมูลซ้ำหรือรหัสสาขาไม่ถูกต้องว่าระบบแจ้งเตือนเหมาะสม

### 4. ทีมและรายชื่อนักกีฬา

- สร้างทีมโดยเลือกรายการแข่งขัน สาขา ชื่อทีม และสถานะ
- เพิ่มรายชื่อนักกีฬาเข้าทีมด้วยรหัสนักศึกษา
- ทดสอบบทบาท เช่น นักกีฬา กัปตัน ผู้ฝึกสอน หรือสำรอง
- อนุมัติหรือเปลี่ยนสถานะทีม แล้วตรวจสอบผลในหน้าสาธารณะ `นักกีฬา`

### 5. การแข่งขันและผลการแข่งขัน

- สร้างรายการแข่งขัน โดยเลือกกีฬา ปีการศึกษา รูปแบบ และสถานะ
- สร้างแมตช์ โดยเลือกรายการแข่งขัน ทีม วันเวลา สนาม กรรมการ และสถานะ
- บันทึกผลการแข่งขันด้วยคะแนนทีม 1 และทีม 2
- ตรวจสอบว่าแมตช์ที่ยังไม่จบแสดงในหน้าสาธารณะ `ตารางแข่งขัน`
- ตรวจสอบว่าแมตช์ที่บันทึกผลแล้วแสดงในหน้าสาธารณะ `ผลการแข่งขัน`

### 5.1 ทัวร์นาเมนท์หลายกีฬา

- เปิดเมนู `การแข่งขัน` แล้วกด `เพิ่มรายการแข่งขัน`
- ระบุชื่อรายการ และเลือกกีฬาอย่างน้อย 2 รายการจากฐานข้อมูลกีฬา
- บันทึก แล้วตรวจสอบคอลัมน์ `กีฬา` ว่าแสดงกีฬาที่เลือกทั้งหมด
- เปิดแก้ไขรายการเดิม เพิ่มหรือนำกีฬาออก แล้วบันทึกอีกครั้ง
- ตรวจสอบว่ารายการเดิม ทีม และแมตช์ยังคงอยู่ และไม่สามารถลบกีฬาที่ถูกใช้งานในทัวร์นาเมนท์ได้

### 6. ข่าวสาร

- สร้างข่าวใหม่ โดยระบุประเภท หัวข้อ ลิงก์ย่อ คำโปรย เนื้อหา รูปปก และสถานะ
- ทดสอบสถานะ `published`, `draft`, และ `archived`
- ทดสอบปักหมุดข่าว
- ในส่วน `AI NEWSROOM` เลือกกีฬา รายการ แมตช์ รูปแบบข่าว และโทนการเขียน แล้วกด `สร้างร่างด้วย AI`
- ตรวจสอบว่า AI เติมหัวข้อ คำโปรย และเนื้อหาให้ โดยไม่เปลี่ยนคะแนน ทีม หรือข้อเท็จจริงของแมตช์
- กด `สร้างแบนเนอร์` แล้วทดสอบเทมเพลต `Match Day`, `Match Result` และ `Sport Spotlight`
- อัปโหลดรูปการแข่งขัน ปรับสี การจัดข้อความ ขนาด/ตำแหน่งรูป และลากหัวเรื่องบน Canvas
- กด `ดาวน์โหลด PNG` เพื่อตรวจไฟล์ภาพ และกด `ใช้เป็นรูปปกข่าว` เพื่อตรวจว่าลิงก์รูปปกถูกเติมกลับในฟอร์ม
- ตรวจสอบข่าวที่เผยแพร่ในหน้าสาธารณะ `ข่าวสาร`

### 7. แผนงาน

- สร้างงานใหม่ โดยระบุชื่องาน รายละเอียด หมวดงาน ความสำคัญ สถานะ กำหนดเสร็จ และผู้รับผิดชอบ
- เปลี่ยนสถานะงาน เช่น ต้องทำ กำลังทำ ติดปัญหา และเสร็จแล้ว
- ตรวจสอบว่างานค้างแสดงในแดชบอร์ดถูกต้อง

### 8. ผู้ดูแลระบบ

- สร้างผู้ใช้ทดสอบโดยระบุอีเมล ชื่อ รหัสผ่าน บทบาท สาขา และกีฬาที่รับผิดชอบ
- ทดสอบบทบาทหลัก:
  - `super_admin`: เห็นทุกเมนู
  - `admin`: จัดการข้อมูลส่วนใหญ่ รวมงานทะเบียนนักศึกษาและทีม
  - `sport_head`: จัดการงานกีฬาและการแข่งขัน
  - `result_officer`: บันทึกผลการแข่งขัน
  - `public_relations`: จัดการข่าวสาร
  - `viewer`: ดูข้อมูลและแดชบอร์ด
- ทดสอบปิดใช้งานผู้ใช้ แล้วตรวจสอบว่าไม่สามารถเข้าสู่ระบบได้

### 9. รายงาน

- สร้างรายงานจากหน้า `รายงาน`
- เลือกประเภทรายงาน เช่น สรุปผู้บริหาร ผลการแข่งขัน ทะเบียนนักกีฬา หรือคุณภาพข้อมูล
- เลือกรูปแบบ `JSON`, `CSV` หรือทั้งสองแบบ
- ตรวจสอบไฟล์ผลลัพธ์ใน `public/reports/`

## การทดสอบอัตโนมัติ

สามารถรัน smoke test ของ UI ได้ด้วยคำสั่งต่อไปนี้บน Windows:

```bash
npm.cmd run test:ui
```

สคริปต์จะเปิด PHP server ชั่วคราว ใช้ SQLite แยกสำหรับการทดสอบ และบันทึกภาพหน้าจอไว้ที่ `storage/ui-checks/` โดยไม่เขียนทับฐานข้อมูลจริง `storage/prsport.sqlite`

## ข้อควรระวังในการทดสอบ

- หากทดสอบบนฐานข้อมูลจริง ให้หลีกเลี่ยงการลบข้อมูลที่ไม่ได้สร้างเพื่อทดสอบ
- แนะนำให้ตั้งชื่อข้อมูลทดสอบให้ชัดเจน เช่น `ทดสอบ-ฟุตบอล-001` หรือ `UI Test Task`
- หากต้องการทดสอบบัญชีผู้ดูแลเริ่มต้นใหม่ ให้ใช้ฐานข้อมูลว่างหรือฐานข้อมูลสำรอง
- หากฟังก์ชัน AI ไม่พร้อมใช้งาน ระบบยังทำงานด้วย `local-summary` ได้

## แนวทางแก้ปัญหาเบื้องต้น

- เข้าสู่ระบบไม่ได้: ตรวจสอบอีเมล รหัสผ่าน และสถานะ `is_active` ของผู้ใช้
- ไม่เห็นเมนูหลังบ้าน: ตรวจสอบว่าล็อกอินสำเร็จและบทบาทของผู้ใช้มีสิทธิ์เข้าหน้านั้น
- บันทึกข้อมูลไม่ได้: ตรวจสอบช่องที่จำเป็น เช่น ชื่อกีฬา รหัสนักศึกษา รายการแข่งขัน หรือทีม
- รายงานไม่ถูกสร้าง: ตรวจสอบสิทธิ์ผู้ใช้และสิทธิ์เขียนไฟล์ใน `public/reports/`
- AI เชื่อมต่อไม่ได้: ตรวจสอบ `GEMINI_API_KEY`, firewall, proxy หรือดูรายละเอียดเพิ่มเติมที่ `docs/gemini-ai.md`
